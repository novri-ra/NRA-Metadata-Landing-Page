# RJ Auto Metadata — Structural & Storage Analysis

Reference application audited: **RJ Auto Metadata** (installed distribution /
user data on this machine). Goal: compare architecture and storage conventions
against **NRA-Metadata**, extract standout patterns, and align configuration
management where sensible (encryption preserved).

> Secrets note: all API-key values observed during the audit are REDACTED in
> this document and never committed.

---

## 1. Installation inventory — `C:\Program Files (x86)\RJ Auto Metadata`

### 1.1 Framework detection

| Evidence | Conclusion |
|---|---|
| `python312.dll`, `python3.dll`, `_ssl.pyd`, `_tkinter.pyd`, `unicodedata.pyd`, ... | Python **3.12** standard library extensions shipped loose (portable/onedir bundle) |
| `customtkinter/`, `tk/`, `tcl/` | **CustomTkinter (CTk)** GUI over Tk — same stack as NRA-Metadata |
| `cryptography/`, `pydantic_core/`, `jiter/`, `greenlet/`, `sqlalchemy/` | Third-party Python packages present as raw folders |
| `RJ Auto Metadata.exe` (296 MB) with **no embedded `MEI` CArchive** | Not a classic PyInstaller onefile/`_internal` layout; best match is a portable PyInstaller-style or custom onedir bundle (packaged Python + loose packages) |
| `unins000.dat` / `unins000.exe` | Installed via **Inno Setup**, so it is an official install, not just a folder copy |

### 1.2 Bundled compute/media tooling (identical trio as NRA)

| Tool | RJ bundled artifact | NRA-Metadata |
|---|---|---|
| ExifTool | `tools/exiftool/exiftool.exe` **v13.26** (full Strawberry-Perl dist: `perl.exe`, `perl532.dll`, `exiftool.pl`) | `tools/exiftool/` (same Perl distribution model) |
| FFmpeg | `tools/ffmpeg/bin/{ffmpeg,ffprobe,ffplay}.exe` | `tools/ffmpeg/` (video frame extraction) |
| Ghostscript | `tools/ghostscript/bin/gswin64c.exe` + `gsdll64.dll` | `tools/ghostscript/` (vector/AI/EPS previews) |
| Image/vision libs | `cv2`, `PIL`, `cairosvg`, `cairo`, `lxml` | PIL + Edge/svglib/GS fallbacks |
| Audio | `_sounddevice_data/portaudio-binaries`, `websockets` | (not present — feature gap, see §5) |
| ML/plotting extras | `scipy`, `pandas`, `matplotlib`, `numpy` | (only stdlib + sqlite used) |

**Conclusion:** the reference and NRA share the identical media-tool philosophy
(ExifTool + FFmpeg + Ghostscript, preview-before-embed). There is **no** bundled
CSV/XMP *template* folder; platform CSV exports are generated by code instead —
same design as NRA's `csv_exporter`.

## 2. User-data storage — `C:\Users\Administrator\Documents\RJ Auto Metadata`

| File | Content | NRA equivalent |
|---|---|---|
| `config.json` (4.4 KB, **plaintext**) | all settings incl. **API keys in plaintext** | `config.enc` — **DPAPI-encrypted** (NRA is superior here) |
| `processed_cache.json` (empty `{}`) | processed-file marker cache, JSON | `cache.db` (SQLite, SHA-256 keyed, evicts fallback records) — NRA is superior |

### 2.1 Reference config schema (keys observed)

- `config_version`, `input_dir`, `output_dir`, `delay`, `workers`, `rename`,
  `auto_kategori`, `auto_foldering`, `auto_retry`
- `api_keys` (legacy flat list) + **`api_keys_by_provider`**:
  `Gemini, OpenAI, OpenRouter, iLabs, Groq, KoboiLLM, Mistral, Blackbox, Custom`
- `models_by_provider`, `selected_model_by_provider` (e.g. `Gemini ->
  models/gemini-2.5-flash`, newer `models/gemini-3.8-flash`)
- `custom_base_url` (OpenAI-compatible endpoint, e.g.
  `https://generativelanguage.googleapis.com/v1beta/openai/`)
- `model`, `keyword_count` (49 default), `priority` (`Detailed`), `embedding`
  (`Enable`/`Disable`), `api_key_paid`
- `console_visible`, `theme`, `last_saved`, `analytics_enabled`,
  `installation_id`
- Title/description constraints: `title_min_words|max_chars`,
  `desc_min_words|max_chars` + `custom_*` variants
- `hint`, `custom_instruction`, `inject_keywords`

### 2.2 Key observation

The reference stores **API keys in clear-text JSON under Documents**. NRA-Metadata
already encrypts them (DPAPI on Windows). The adaptation below therefore:

1. adopts the reference's *convention* of a **user-Documents data directory** —
   but writes `config.enc` (encrypted), never plaintext keys;
2. adds a **read-only / one-way sync** from the reference config so users
   migrating from RJ Auto Metadata do not have to retype API keys.

## 3. Workflow comparison (queue, ExifTool writing, UI)

| Aspect | RJ Auto Metadata | NRA-Metadata | Verdict |
|---|---|---|---|
| GUI | CustomTkinter, dark theme | CustomTkinter, dark theme, bespoke component widgets | Equivalent |
| Concurrency | `workers` (1..N) + `delay` (s) in config | `FileWorkerPool` (threads, pause/cancel, live progress 0..1) | **NRA superior** |
| Queue processing | worker pool → sink dir | pool → `Processed Assets/` + `Metadata CSV/`, companion `.eps/.ai` sync, optional ZIP | **NRA superior** |
| Metadata write | ExifTool (13.26) | ExifTool via `ExifToolClient` w/ AI-metadata sanitization | Equivalent (same tool) |
| Cache | `processed_cache.json` (plain, empty) | SQLite cache + fallback-eviction + cache-hit labeling | **NRA superior** |
| Secrets | Plaintext keys in `config.json` | `config.enc` DPAPI | **NRA superior** |
| Previews | cv2 / cairosvg | PIL + FFmpeg + Ghostscript + Edge/svglib | Equivalent |
| Providers/modals | Gemini/OpenAI/OpenRouter/iLabs/Groq/KoboiLLM/Mistral/Blackbox/Custom | Gemini/OpenAI/Mistral/Groq/9router + failover + key rotation | NRA has fewer, but with rotation/failover plumbing |

### 3.1 Reference-only features (backlog candidates)

| Reference feature | Notes for NRA |
|---|---|
| `delay` between files | easy worker-pool addition (sleep in `_process_file`) |
| `rename` output files | optional, per-file |
| `auto_kategori` / `auto_foldering` | maps AI category → Shutterstock-style subfolder |
| `auto_retry` | NRA already has retry/backoff + 429 failover — set to `true` lineage |
| OpenAI-compatible **Custom provider** (`custom_base_url`) | NRA router has `normalize_base_url`, only worker wiring to a editable URL remains |
| `embedding` toggle | vectors beyond metadata scope |
| Audio (`sounddevice`, `websockets`) | out of scope for stills/vectors/video |

## 4. Changes applied in NRA-Metadata

### 4.1 Configurable data directory (mirrors reference convention, encrypted)

`backend/core/config_manager.py`:
- `set_config_dir(path=None)` / `get_config_dir()` — points `config.enc`,
  `config.json` (migration), and `cache.db` at a chosen directory.
- Default resolution `_default_data_dir()`:
  1. `NRA_CONFIG_DIR` env var (highest precedence);
  2. Windows → `%USERPROFILE%\Documents\NRA Metadata` (created on demand);
  3. fallback → current working directory (unchanged Linux/CI behavior).
- `apps/desktop/src/main.py` calls `set_config_dir()` + best-effort RJ import at
  startup; `apps/desktop/src/ui/main_window.py#_flush_cache` and
  `scripts/purge_cache.py` now use the dynamic `DB_PATH`.

### 4.2 One-way sync from RJ Auto Metadata

`backend/core/config_manager.py`:
- `find_rj_config(path=None)` — locates
  `Documents\RJ Auto Metadata\config.json` (or explicit path).
- `import_rj_config(path=None, merge=True)`:
  - reads the reference **plaintext** config;
  - maps providers **Gemini / OpenAI / Groq / Mistral** into the encrypted NRA
    `api_keys` store (newline-joined key pool, so NRA key rotation still works);
  - never overwrites existing NRA keys by default (`merge=False` to replace);
  - carries model selection (`models_by_provider`) and non-sensitive hints
    (`rj_*`: `default_model`, `priority`, `keyword_count`, `embedding`,
    `custom_base_url`);
  - **writes back only via `save_config` → DPAPI `config.enc`**; nothing
    plaintext is ever persisted by NRA.
- `apps/cli/src/main.py`: new `--config-dir` and `--import-rj [PATH]` flags.

### 4.3 Verified

- `py_compile` clean on all touched modules.
- Behaviour harness (Linux, stubbed DPAPI): config-dir resolution + env override,
  `find_rj_config`, import with skip/merge semantics, encryption round-trip,
  `merge=False` replace — all pass.
- Existing unit-test baseline unchanged: `Ran 1 test`,
  `ModuleNotFoundError: No module named 'google'` (env dependency gap, parity kept).

## 5. Recommendations (backlog, not applied)

1. `delay` option in worker pool options (smooth rate limiting).
2. Configurable **Custom provider base URL** threaded through login modal → router.
3. `auto_foldering` (category-based output subfolders) in `worker_pool`.
4. Optional XMP sidecar export for AI-generated metadata portability.
5. Kill/leave `RJ Auto Metadata` import at desktop startup — currently only runs
   when the NRA store has **no** keys at all.
