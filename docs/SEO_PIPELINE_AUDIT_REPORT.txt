4. JSON RESPONSE PARSER & ERROR HANDLING GAP

TEMUAN 4.1 — Parser Terlalu Simplistis
  _parse_json() (baris 226-235):
    try:
        start = text.find('{')
        end = text.rfind('}')
        if start != -1 and end != -1:
            return json.loads(text[start:end+1])
        return json.loads(text)
    except json.JSONDecodeError:
        return self._fallback_metadata()

  Masalah:
  a) Jika AI mengembalikan response dengan multiple JSON objects,
     rfind('}') akan mengambil brace terakhir yang mungkin bukan
     penutup object yang benar.
  b) Jika AI mengembalikan ```json\n{...}\n```, find('{') akan
     bekerja TAPI jika ada nested markdown formatting, bisa gagal.
  c) Response yang valid tapi field-nya tidak sesuai (misal "name"
     instead of "title") akan diterima tanpa validasi.

TEMUAN 4.2 — Tidak Ada Validasi Field Setelah Parse
  Setelah json.loads() berhasil, tidak ada pengecekan apakah dict
  mengandung field wajib: "title", "description", "keywords".
  Jika AI mengembalikan {"text": "...", "tags": [...]}, parser
  akan return dict tanpa field yang dibutuhkan. clean_metadata()
  (baris 235-241) akan menggunakan default empty string/list.

TEMUAN 4.3 — Tidak Ada Logging Response Mentah Saat Parse Gagal
  Ketika JSONDecodeError terjadi, response text mentah dari AI TIDAK
  di-log ke file atau console. Ini membuat debugging sangat sulit
  karena tidak ada evidence tentang apa yang AI kembalikan.

TEMUAN 4.4 — Gemini Response Langsung json.loads Tanpa Fallback
  Baris 129: return json.loads(response.text)
  Jika Gemini mengembalikan response yang bukan valid JSON (meskipun
  response_mime_type="application/json"), exception akan terjadi dan
  LANGSUNG masuk ke except block yang mungkin memicu fallback tanpa
  retry. Ini berbeda dengan provider lain yang melalui _parse_json().
